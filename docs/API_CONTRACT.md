# API Contract

Authoritative HTTP contract for GridMitra. Field names, units, and statuses follow `docs/DATA_CONTRACT.md`. All numeric fields carry explicit units in their names or in the contract below.

## `GET /api/v1/health`

Returns three separate fields. A database failure must not make API health appear completely unavailable.

```json
{
  "api": "ok",
  "solver": "ok",
  "database": "ok"
}
```

- `api`: `ok` when the service is up.
- `solver`: `ok` when CBC can be reached or invoked (checked lazily or on request).
- `database`: `ok` when the database connection is ready, otherwise `unavailable`. This value never downgrades `api`.

## `GET /api/v1/scenarios/demo`

Returns the committed 24-hour scenario. The source file is `data/demo_scenario.json`, served from the repository in development and from the backend image (`/app/data/demo_scenario.json`) in containers.

## `POST /api/v1/optimize`

Accepts a scenario with exactly 24 hourly input records and configuration objects for the battery, diesel generator, and operator preferences.

### Request

- `name`: string.
- `hours`: exactly 24 records, each with `hour` (0–23), and non-negative demand and availability values.
- `battery`: `capacity_kwh`, `initial_soc_kwh`, `min_soc_kwh`, `max_soc_kwh`, `max_charge_kw`, `max_discharge_kw`, `charge_efficiency`, `discharge_efficiency`, `reserve_target_kwh`, `throughput_cost_per_kwh`.
- `diesel`: `max_power_kw`, `cost_per_kwh`, `emission_kg_per_kwh`.
- `objective`: **bounded operator preferences**, not unrestricted weights:
  - `carbon_price_per_kg`: operator-adjustable within a documented range.
  - The P1 penalty, reserve-shortfall penalty, and P2–P4 safety penalties are **backend-controlled** and cannot be changed by the frontend.

### Response

```json
{
  "status": "optimal | emergency_plan | failed",
  "dispatch_hours": [],
  "summary": {},
  "explanations": [],
  "warnings": []
}
```

- `status`: normalized solver outcome only. Raw CBC strings are never exposed.
  - `optimal`: solved to optimality.
  - `emergency_plan`: solved, but demand or reserve could not be fully met within physical limits; unmet-load warnings are returned instead of a failure.
  - `failed`: no usable dispatch; the response contains no `dispatch_hours` values.
- `dispatch_hours`: array, one entry per hour, containing solar, wind, diesel, battery charge/discharge, and SOC values in `kwh`/`kw`.
- `summary`: totals with explicit units — `total_cost` (currency), `diesel_energy_kwh`, `co2_kg` (as `kg_co2`), `renewable_share_percent`, and reliability values.
- `explanations`: plain-language observations, generated by rules.
- `warnings`: structured warnings.

### Warnings

- Critical demand shortfall: standardized field `p1_unserved_kwh`.
- Unserved energy: `unserved_kwh` object with separate `p1`, `p2`, `p3`, and `p4` values.
- Terminal reserve shortfall: `reserve_shortfall_kwh`.

The UI must show a warning whenever `p1_unserved_kwh` or `reserve_shortfall_kwh` is greater than zero.

## Error responses

### Validation failure — HTTP 422

A consistent error object:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Battery initial charge cannot be below the configured minimum reserve.",
    "fields": ["battery.initial_soc_kwh"]
  }
}
```

Invalid input is rejected before any solver runs.

### Solver failure — HTTP 500 or structured failed result

If the solver cannot produce a usable plan, the API returns a structured `failed` result without `dispatch_hours`, or HTTP 500 with the same error shape. A solver failure must never look like a valid dispatch.

## Implementation status

The contract above is the target. The current starter implementation is narrower and must be migrated:

- `GET /api/v1/health` currently returns `api` and `database`; `solver` is added with this contract.
- `POST /api/v1/optimize` currently returns `status` of `optimal` or `feasible`, field `hours` (not `dispatch_hours`), and 2-tier `unserved_critical_kwh` / `unserved_flexible_kwh` (not P1–P4).
- No export or run-history endpoints exist yet; `GET /api/v1/runs` and `GET /api/v1/runs/{id}/export` are planned.
